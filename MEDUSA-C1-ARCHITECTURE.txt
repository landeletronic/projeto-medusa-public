3. MODELO LOGICO RELACIONAL (C1.3 itens 3-4)
================================================================================

  Banco: SQLite jobs.sqlite3 (mesmo arquivo). Prefixo registry_*. Sem FK
  declaradas (padrao do codigo; integridade via aplicacao + UNIQUE).

  registry_persons(
    id TEXT PRIMARY KEY,                    -- uuid4 hex, nao derivado do nome
    kind TEXT NOT NULL CHECK(kind IN ('PF','PJ')),
    display_name TEXT NOT NULL,             -- nome de apresentacao
    legal_name TEXT,                        -- nome civil / razao social
    social_name TEXT,                       -- nome social / fantasia
    status TEXT NOT NULL DEFAULT 'ACTIVE' CHECK(status IN ('ACTIVE','INACTIVE')),
    created REAL NOT NULL, updated REAL NOT NULL)
  CREATE INDEX registry_persons_name_idx ON registry_persons(display_name);
  CREATE INDEX registry_persons_kind_idx ON registry_persons(kind);

  registry_identifiers(
    id TEXT PRIMARY KEY, person_id TEXT NOT NULL, id_type TEXT NOT NULL
    CHECK(id_type IN ('CPF','CNPJ','RG','PASSPORT','OTHER')),
    id_value TEXT NOT NULL,                 -- so digitos p/ CPF|CNPJ
    verified INTEGER NOT NULL DEFAULT 0, created REAL NOT NULL,
    UNIQUE(id_type, id_value))
  Regras: CPF 11 digitos + digitos verificadores mod11; CNPJ 14 + mod11;
  formatos com pontuacao sao normalizados (so digitos); RG/PASSPORT/OTHER
  livres (min 3 chars). Duplicado global -> 409 conflito, sem fusao.

  registry_roles(
    id TEXT PRIMARY KEY, person_id TEXT NOT NULL, role TEXT NOT NULL
    CHECK(role IN ('CLIENT','COUNTERPARTY','LAWYER','REPRESENTATIVE',
                   'WITNESS','EXPERT','OTHER')),
    context TEXT NOT NULL DEFAULT '', started REAL, ended REAL,
    created REAL NOT NULL,
    UNIQUE(person_id, role, context))
  Nesta etapa: escrita limitada a role=CLIENT (outros retornam 400 com mensagem
  de pendencia futura). Leitura lista todos.

  registry_person_history(
    id TEXT PRIMARY KEY, person_id TEXT NOT NULL, op TEXT NOT NULL,
    before_json TEXT, after_json TEXT, actor_id TEXT, actor_username TEXT,
    ip TEXT NOT NULL, created REAL NOT NULL)
  CREATE INDEX registry_person_history_person_idx ON registry_person_history(person_id);

  registry_doc_labels(
    id TEXT PRIMARY KEY,
    document_id TEXT NOT NULL UNIQUE,       -- id tecnico OCR (uuid hex)
    job_id TEXT,                            -- job de origem (informativo)
    friendly_name TEXT NOT NULL,            -- rotulo (1..120 chars)
    doc_type TEXT,                          -- identification|residence|...
    origin TEXT NOT NULL DEFAULT 'manual',
    ocr_state TEXT, review_state TEXT,      -- espelhos informativos
    created REAL NOT NULL, updated REAL NOT NULL)

  registry_doc_label_history(
    id TEXT PRIMARY KEY, doc_label_id TEXT NOT NULL, op TEXT NOT NULL,
    before_json TEXT, after_json TEXT, actor_id TEXT, actor_username TEXT,
    ip TEXT NOT NULL, created REAL NOT NULL)

  registry_doc_person_links(
    id TEXT PRIMARY KEY, doc_label_id TEXT NOT NULL, person_id TEXT NOT NULL,
    state TEXT NOT NULL CHECK(state IN ('CONFIRMED','PENDING','DISPUTED')),
    created REAL NOT NULL, updated REAL NOT NULL,
    UNIQUE(doc_label_id, person_id))

  Cardinalidades: person 1-n identifiers; person 1-n roles; person 1-n history;
  doc_label 1-1 document_id; doc_label 1-n history; doc_label n-n person via
  links (state explicito). Dossie/processo: 0 (futuro).

================================================================================

  BACKUP: (a) sqlite3 backup API para jobs.sqlite3 (consistente com WAL e
  conexoes concorrentes; sem copiar arquivo quente); (b) cp -a do codigo
